# FR10.7: Shared Edge ML Model Administration & User-Specific AI Settings

## 1. Objective
Separate shared system-level Edge Machine Learning model management (e.g. FinBERT INT8 ONNX transformer) from individual user-level AI preferences. Shared server model weights and disk storage must be managed exclusively by administrators in **Administration &rarr; System Maintenance**, while user-specific LLM parameters (Ollama endpoints, personal API keys) and read-only active inference status remain in **Profile &rarr; AI & Intelligence**.

---

## 2. Background & Problem Statement
In multi-tenant server deployments, model weights (such as `finbert_int8.onnx` ~105.2 MB and `vocab.txt`) are stored globally on the server filesystem (`data/models/`). 
Previously, any authenticated standard user could trigger model downloads or delete model files from their personal user profile. Deleting a shared model degraded sentiment analysis across the entire instance for all users back to the fallback financial lexicon, creating an availability and denial-of-service hazard.

---

## 3. Scope & Responsibilities

### 3.1. Administration (`/admin/maintenance`)
- **Audience:** System Administrators (`user.is_admin == true`).
- **Capabilities:**
  - View all registered models in the Edge ML catalog.
  - Initiate background downloads of shared model weights to server storage.
  - Monitor real-time download progress percentages and byte counts.
  - Delete downloaded models to free server disk space.
  - View active engine status and failure diagnostics.

### 3.2. User Profile (`/profile?tab=ai`)
- **Audience:** All Authenticated Users.
- **Capabilities:**
  - **Read-Only Status Badge:** View whether the active sentiment engine is currently running on the high-precision FinBERT ONNX transformer or the fast financial lexicon fallback.
  - **Admin Navigation Link:** For administrators, provide a quick link to `/admin/maintenance` to manage server weights.
  - **Interactive Testing Sandbox:** Test any financial headline or earnings phrase against the active sentiment engine.
  - **Personal LLM Configuration:** Configure personal local LLM endpoints (Ollama URL, model name) and cloud LLM provider preferences.

---

## 4. API & Security Specifications

### 4.1. Endpoints & Access Control
| Endpoint | Method | Role (Server Mode) | Role (Desktop/Standalone) | Description |
| :--- | :--- | :--- | :--- | :--- |
| `/api/v1/ml/models` | `GET` | All Active Users | All Active Users | Lists model status & active engine |
| `/api/v1/ml/models/{id}/progress` | `GET` | All Active Users | All Active Users | Returns download progress |
| `/api/v1/ml/models/{id}/download` | `POST` | **Admin Only (403 Forbidden for non-admin)** | All Active Users | Starts background download |
| `/api/v1/ml/models/{id}` | `DELETE` | **Admin Only (403 Forbidden for non-admin)** | All Active Users | Deletes model weights from disk |
| `/api/v1/ml/sentiment/test` | `POST` | All Active Users | All Active Users | Evaluates headline sentiment |

---

## 5. Non-Functional Requirements
- **NFR1: Non-disruptive:** Standard users must not experience broken views or missing sentiment capabilities; they continue using whichever engine the server has active.
- **NFR2: Standalone Mode Parity:** In desktop/Android standalone mode where deployment mode is not server, the primary user retains administrative capabilities.
- **NFR3: Security & Authorization:** Unauthorized deletion or download attempts return HTTP 403 with descriptive error messages.

# Feature Specification: Salary Component Breakdown & Section 10(13A) HRA Exemption Logging (FR16.5)

**Feature ID:** FR16.5  
**Status:** 📝 Planned  
**Title:** Salary Component Breakdown & Section 10(13A) HRA Exemption Calculation Engine  
**GitHub Issue:** [#532](https://github.com/aashishbhanawat/ArthSaarthi/issues/532)  
**Excel Calculator Parity Benchmark:** `local/TaxCalc_2027.xlsx` (Sheet `IT 2026-27`, Cell `D101`)  
**User Story:** As a salaried taxpayer, I want to log my salary components (Basic Salary, Dearness Allowance, HRA Received, Rent Paid, and Metro/Non-Metro location), so that ArthSaarthi can automatically calculate my Section 10(13A) HRA exemption and taxable net salary.

---

## 1. Sub-Task Breakdown & Implementation Modules

1. **Module 1.1 (Database Schema & Model Extension):** Extend `IncomeEntry` SQLAlchemy model with optional encrypted salary breakdown fields (`basic_amount`, `hra_amount`, `da_amount`, `rent_paid`, `is_metro`), plus Alembic migration.
2. **Module 1.2 (HRA Exemption Math Engine):** Implement statutory Section 10(13A) HRA Exemption Service (`SalaryExemptionService`) benchmarked 100% against `local/TaxCalc_2027.xlsx` (Cell `D101`).
3. **Module 1.3 (Backend APIs & Pydantic Validation):** Update `/api/v1/income/entries` REST endpoints (`POST`, `PUT`, `GET`) and Pydantic schemas with salary component validation (`hra_amount <= gross_amount`, `basic_amount <= gross_amount`).
4. **Module 1.4 (Frontend UI & Collapsible Form Drawer):** Add optional "Salary Breakdown & HRA Exemption Calculator" expandable drawer to `IncomeEntryModal.tsx` and render net taxable salary / exempt HRA badges on `IncomePage.tsx`.

---

## 2. Backend & Frontend Responsibilities

* **Backend (`backend/app/models/income.py` & `backend/app/services/salary_exemption_service.py`):**
  - Model definitions for salary breakdown fields.
  - Pydantic schema validation (`app/schemas/income.py`).
  - Calculate HRA Exemption u/s 10(13A):
    $$\text{HRA Exemption} = \max\left(0, \min\left(\text{HRA Received},\; \text{Rent Paid} - 10\% \times (\text{Basic} + \text{DA}),\; k \times (\text{Basic} + \text{DA})\right)\right)$$
    where $k = 50\%$ for Metro cities (Mumbai, Delhi, Kolkata, Chennai) and $k = 40\%$ for Non-Metro cities.
  - Compute Net Taxable Salary (`gross_salary - hra_exemption`).
* **Frontend (`frontend/src/components/IncomeEntryModal.tsx` & `frontend/src/pages/IncomePage.tsx`):**
  - Interactive "Salary Components & HRA Calculator" toggle in entry modal.
  - Live calculation preview of HRA Exemption and Net Taxable Salary as the user types.
  - Privacy Mode masking (`usePrivacy`).

## 3. Test Plan & Corner Cases

### 3.1. Corner Cases
* **Rent Paid Less Than 10% of Basic+DA:** When `Rent Paid <= 10% * (Basic + DA)`, HRA Exemption evaluates to exactly `₹0.00`.
* **Zero HRA Received:** When salary contains no HRA component (`hra_amount = 0`), exemption evaluates to `₹0.00`.
* **Rent Paid Exceeds Salary:** Validated to prevent negative net salary calculations.
* **Metro vs Non-Metro Cap Switching:** Toggling Metro (50% cap) vs Non-Metro (40% cap) updates exemption limit instantly.
* **Non-Salaried Income:** Freelance, Rental, and Dividend income entries bypass salary component fields cleanly without raising validation errors.

## 6. Database Schema & Security Encryption (`EncryptedString`)

To protect user financial privacy on local desktop (PyInstaller) and mobile (Android SQLite) databases, all monetary fields utilize `EncryptedString` (AES-256-GCM encryption key managed by `KeyManager`):

```sql
ALTER TABLE income_entries ADD COLUMN basic_amount VARCHAR;  -- EncryptedString
ALTER TABLE income_entries ADD COLUMN hra_amount VARCHAR;    -- EncryptedString
ALTER TABLE income_entries ADD COLUMN da_amount VARCHAR;     -- EncryptedString
ALTER TABLE income_entries ADD COLUMN rent_paid VARCHAR;     -- EncryptedString
ALTER TABLE income_entries ADD COLUMN is_metro BOOLEAN DEFAULT FALSE;
ALTER TABLE income_entries ADD COLUMN hra_exemption VARCHAR; -- EncryptedString (computed)
```
